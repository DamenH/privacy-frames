# Canonical path admission loop

`CanonicalAdmission.lean` proves a property of a simplified admission loop for any finite list of strings. If it returns true, every string satisfies the supplied `allowed` predicate, the list contains no duplicates, and none appeared in the initial `seen` list. This is unbounded in the number and values of strings. Run `python3 formal/path-lean/check.py` using the pinned Lean installation documented in `formal/lean/README.md`; it kernel-checks with `--trust=0`, checks the reported axiom dependencies, and tests that removing either loop condition prevents the existing proof from type-checking. These mutation checks are proof sensitivity checks, not proofs of concrete attacks. The theorem depends on Lean's `propext` and `Quot.sound`; it has no `sorryAx` dependency.

The intended correspondence is the loop in `src/runtime/admission.ts`: each resource yields the `resourceURL(...).href` target, `allowed` represents `resolved !== appURL && resolved.startsWith(appURL)`, and the list `seen` represents the `resolvedPaths` Set. The implementation throws on a disallowed or repeated target, then inserts it into the Set. This mapping is by inspection, not a machine-checked translation or a theorem about JavaScript. TypeScript iteration, exceptions, URL construction, string comparison and Set behavior are assumed to match the abstract loop. The proof also does not establish that the app-base predicate means confinement under browser URL parsing, that generated URLs reach this check, or that subsequent runtime code preserves these results. The selected two-browser tests cover individual implementation cases, not all inputs or browsers.
